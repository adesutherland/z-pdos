## LD-003: Exact XMIT segment boundary termination

- Type: defect
- Status: Done for the reached native XMIT route
- Authorization: Required for the shared SDK/cREXX PD-033 Stage 3 package and native z/OS reference qualification.
- Target: Native XMIT writer.
- Observation: A logical payload ending with a full 253-byte segment omitted its final-segment flag. The next record then appeared nested; the rebuilt batch RXC transport reached this boundary.
- Implementation: Mark the last segment from the remaining payload size, including 253 bytes. Preserve every payload byte and output size.
- Validation: The independent segment decoder fails at 253 bytes before the repair. Check neighbouring sizes, multiple full segments, exact payload reconstruction and guard bytes under ASan/UBSan; regenerate and extract the actual RXC transport, then qualify native RECEIVE/execution.
- Result (14 October): All 34 linker checks passed in normal and ASan/UBSan builds. The repaired shared batch package exported/extracted all four tools; native z/OS 1.5 RECEIVE restored all six probe/tool members with IEBCOPY RC 0. Fresh RXC/RXAS/RXVM and RXLINK/RXVM chains passed with exact generated bytecode readback and portable execution. Other inherited backends and release publication remain separate.
- Acceptance: Boundary controls and actual package extraction pass; native qualification is recorded with the shared package gate. Retain result summaries only.
