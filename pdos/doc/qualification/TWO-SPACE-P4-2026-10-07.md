# PD-003 P4 C console, presentation and transcript, 7 October 2026

P4 closes the selected console/presentation gate in fresh diagnostic IPLs.
The four display models, attached Telnet 3215 monitor, line-only primary,
exclusive line-input handoff, native FULLSCR and capture-gap behavior now have
guest evidence. PCOMM and an opt-in native application use the reusable U C
presentation boundary. Normal-image integration remains P5.

## Implementation

The portable C model and encoder in `twospace_console.c` implement explicit
model geometry, coded buffer addresses, SF/SBA/IC/RA validation, header/footer,
scrolling and entry layout. K's C31 endpoint validates complete U request,
field-vector and text spans before submission. Privileged channel operations
remain in `twospace_channel.asm`. The 16 KiB stream/input workspaces replace
the earlier fixture's 2 KiB/256-byte channel limits.

Neutral SVC200 exposes the frozen capabilities, logical line/screen requests,
separate monitor status and prompt input selection. The U31 library computes
the model layout and issues checked requests; PCOMM uses it when built with
PDOS_TWO_SPACE. The explicit ELF C64 linkage adapter preserves full pointers,
and a native U64 control writes its capability reply to a buffer above 4 GiB.
Unchanged CMS/TSO line adapters use the same K driver. No separate console
image, table or buffer is placed in 24-bit U storage.

The primary and optional monitor have separate low-real channel workspaces.
The monitor workspace is at real `60000`, outside both DAT arenas; the checked
boot configuration is at `95000`. Dynamic K view and transcript storage is
real-frame-ledger owned. The C31 endpoint occupies 236,070 bytes in the
existing 64-page K service bank. K tables/code/buffers consume no low-U pages.

Hercules's named Telnet 3215 backend has a 150-byte line buffer, including its
CRLF. The line primary therefore reports a 148-byte input limit. Monitor and
line output split longer logical records into no-CR writes followed by one
final CR write, preserving one output record. This is distinct from the
3270's qualified 256-byte entry capacity. The monitor remains output-only
until explicit selection for the next owning line prompt. The selected
device holds its own terminal/I/O leases; unsolicited unowned monitor input
is quarantined until reconnection, rather than becoming a later command.

The versioned append-only transcript records command boundaries, exact native
text, separate OS/application results, screen changes and gaps. It never
wraps or reports discarded output as captured. Root completion commits the
binary transcript to the allocated banked PDOS.STORE extent and verifies
readback. A disconnected monitor records a gap; reconnect prints a visible
TRANSCRIPT GAP marker. Native raw screens record screen changes and an
explicit non-text gap, so they cannot qualify as complete text capture.

Idle line prompts wait on actual device events without a product inactivity
deadline. The guest actor has a separate failure watchdog. Completion still
requires the exact channel status and residual; a wake notification is not
I/O success.

## Reproduction and remaining scope

`two-space-console-app.crexx` builds the native opt-in client, U presentation
library and wide-buffer control from source with the supplied checked C31
library. `two-space-next.crexx` with `console` builds K and its diagnostic
entry. `two-space-console-ipl.crexx` accepts fresh output, checked boot inputs,
core, native app, packer, Hercules directory, model, primary class and monitor
selection. Its optional raw/handoff/disconnect cases remain explicit.

P4 integration exposed and repaired a cold-entry pointer binding before U
lowcore allocation, configuration/workspace overlap with a DAT arena, and
the earlier PCOMM cleanup audit incorrectly treating its suspended parent's
lowcore save as a child leak. The shared caller/ownership contract remains
the P1/P3 design; no second launcher or personality ASCE is introduced.

This closes P4's diagnostic console acceptance. It does not select a normal
successor disk, qualify all released compiler/assembler/file workloads or
change the default boot route. Those are P5 and P6. No publication occurs.
