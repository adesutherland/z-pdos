## Machine, inputs and source build

256 MiB real storage. The main disk is a disposable 100-cylinder 3390 at

they do not replace or operate the managed guest.

## Existing operator media workflow

P6 comparison with the [0.1.1 acceptance](0.1.1-OPERATOR-UAT-2026-10-05.md)
found that the normal successor lacked the operator media dispatch. The
existing algorithms now live once in `media_commands.inc`; the one-ASCE
kernel and the K port use the same source. K supplies copied command data,
checked buffers, registered device selection and interruption-driven channel
completion. This preserves PCOMM's ATTACH/WAIT/DETACH command route.

The final media run `p6-reviewed-media` passes all 18 normal-image checks and
47 numbered operator commands, plus two native COPY operations. It mounts
and selects CMSX01, runs the fresh CMS31 chain and bounded CMS24 IO24, then
selects FIXT01 for allocation, four exact record copies, raw tape operations
and native disk-to-tape-to-disk transfer. It rejects an attempted unmount of the selected FIXT01 at RC 8, then
selects PDOS00 again, unmounts
the exchange disk and shuts down. The CMS exchange remains byte-identical.

The independent export passes five datasets: three text records, one sole
empty variable record, ordered binary bytes and two copies of the unchanged
160-byte FB80 payload. VTOC record layout, unrelated VTOC entries and
unrelated CKD tracks remain unchanged. Native COPY produces one 160-byte
physical AWS record and two file marks; copying back restores two logical
80-byte FB records. Its payload SHA-256 is
`d0aa7996ab5eaa44880bae599c12b01a350caf9912ada7731c61eafe166d725f`.
The incoming read-only tape is unchanged. Root return, empty invocation and
terminal leases, durable transcript and complete attached capture pass.

The media run's K core, PLOAD, handover and U PCOMM hashes match the final
source build exactly. Its observed real-frame peak at service return is
116,740,096 bytes. At stop, the largest free low-U interval is
13,914,112 bytes, starting at 1,814,528; the minimum observed interval is
13,799,424 bytes. These are service-boundary observations, not a claim to
sample every transient private staging allocation.

K C31 is 273,734 bytes in a protected 96-page bank, with a protected
128 KiB C stack. Both remain within the original 4 MiB real bootstrap
reservation and consume no additional low-U virtual pages. PCOMM's
below-line control allocations start beyond the declared fixed CMS24 image;
its C arena stays above the line at 16 MiB. Wider cREXX heaps retain 64 MiB
for 31-bit and 128 MiB for 64-bit profiles.

## Final regression and selection gate

### Review and freeze before qualification

The current candidate completes final code review before qualification, as
required by the repository agent guide and shared workflow. The review covers
native ABI/ownership, protected K and low-U placement, shared media code,
checked U transfers, cleanup/error paths, build selection and the guest actor.
Its source and qualification-input hashes are recorded in
`build/pdos/p6-reviewed-freeze.json`.

Focused checks extract the actual product functions and run C89 ASan/UBSan.
They verify a 44-byte, non-NUL-terminated dataset-name field at its declared
precision, unsigned-long formatting and a zero free-space minimum retained
after storage becomes free. `two-space-review-checks.crexx` retains that check.
The guest result checker now requires exact order and one result per numbered
command. Thirteen recorded normal transcripts pass that stronger check;
duplicate and reversed result controls fail it.

The post-review changes are confined to K formatting bounds and observation
bookkeeping, plus the stricter result checker. Unchanged native loading,
application calls, storage, file and console results are reused with their
original image identities. The reviewed source build, media workflow and
normal/fault/repeated lifecycle qualification exercise the affected candidate.
Any code repair returns to review and a new recorded freeze before affected
qualification; later evidence/documentation review is a separate acceptance
step.

The final reviewed source factory build passes host construction and readback.
The reviewed normal guest passes 18 checks; a second IPL of that stopped disk
passes another 18 checks, including complete capture and durable transcript.
The faulted-PCOMM IPL passes 17 checks with OS 12, unavailable application RC,
K emergency output, released ownership and final wait. The reviewed media
workflow passes 18 checks, 47 ordered command results and five independent
stopped-disk exports. Their exact receipts are `p6-reviewed-bare/run`,
`p6-reviewed-bare/repeated`, `p6-reviewed-rootfault/run` and
`p6-reviewed-media/run` under `build/pdos/`.

The preceding affected regression also passes fresh TSO31, TSO64 ANY and HIGH
compile/assemble/execute chains, all three actual-input paths, native TSO24
IO24 input, native mode-crossing and caller-file return/fault checks, model 5
and line-only nested presentation. Exact stopped-store text, binary and empty
results pass. Model 5 and line-only have the same observed minimum low-U
interval, 13,889,536 bytes, and the same 15,597,568-byte largest interval at
stop. Monitor/display selection adds no low-U reservation.

Those regression paths are unchanged by the final reviewed formatting and
observation fixes; their original image identities remain separate in the
JSON record. The reviewed media and lifecycle runs qualify the affected final
candidate. No source or qualification-input drift occurred after review.
The earlier storage-exhaustion attempts were failed host verification attempts,
not accepted guest results.

Retained recipes are `image.crexx`, `two-space-normal-gate.crexx` (including
`bare` and `rootfault`), `two-space-workload-image.crexx`,
