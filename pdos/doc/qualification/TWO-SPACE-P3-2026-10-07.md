# PD-003 P3 native loading and application calls, 7 October 2026

P3 closes native same-personality loading and synchronous calls in the
diagnostic K/shared-U image. CMS PROGRAM and TSO LINK use the existing
invocation, allocation, caller restoration and cleanup machinery. The normal
PCOMM image and full released compiler/assembler workloads remain P5/P6.

## Implementation

K validates the complete native record stream and materializes relocations
in private staging before publishing a U image. The registry records the
personality, declared mode, placement, entry, runtime owner and image lease.
Ordinary loads retain co-resident images. A fixed-origin CMS call uses the
checked reversible overlay, restoring its caller before the caller resumes.
There is no 24-bit promotion or replacement of a live unrelated image.

CMS SVC202/204 accepts the frozen bounded token list. Its 24-bit inline
continuation and 31-to-24 copied list remain distinct. TSO SVC6 checks the
native control list and copies the selected fenced PARAM list and fullword
values. Null optional parameters are supported. K restores the caller's
AMODE, full registers, floating/access state and lowcore. The native result
projects OS status and application RC separately; K also writes the frozen
32-byte versioned result record. A handled loader error is distinct from the
enclosing application's eventual RC.

The selected TSO64 HIGH SVC8/9 route loads each original AL8 body above
4 GiB and assigns it to the active invocation. DELETE checks that owner's
name and mapping. Fault cleanup also reaps an undeleted body. The source-backed
IARV64 callback now uses the registered invocation's owner, including newly
loaded images. All three unchanged HIGH probes obtain and detach their
128 MiB heaps. The native AMODE31 DELETE ignores the unused upper GPR0 word
left by the C body, as the original one-ASCE handler does.

The allocation, real-frame and placement ledgers now have 128 entries and
each invocation has 128 resource entries. These K structures preserve room
for co-resident images and nested native file/runtime resources. They consume
no additional low-U storage. The C31 service occupies 213,510 bytes in the
existing 64-page K bank.

## Reproduction and scope

Build the native call fixtures with `two-space-p0.crexx`. The CMS24 source
control correction and Classic CMS header form are recorded in the
[P0 amendment](TWO-SPACE-P0-2026-10-06.md#p3-fixture-correction-7-october-2026).
No released application instruction bytes are edited. `tso_pack` adds only
the transport EOF to source-built Classic native streams.

Build file controls with `two-space-p3-fixtures.crexx`, supplying the Classic
tools and a checked unchanged native C31 library build. Build K with
`two-space-next.crexx` and its `calls` selector. Then run
`two-space-call-ipl.crexx` with fresh output, checked boot inputs, the core,
P0 fixtures, the frozen HIGH inputs and file fixtures; select `ordinary`,
`cross` or `missing`. The recipe packs and hashes inputs, reads back the disk,
removes only verified flat intermediates, boots and judges the stopped guest.

These are component/target and diagnostic guest proofs. P4 owns display
models, neutral presentation, the line monitor and transcript. P5 owns the
selectable normal image; P6 owns full unchanged workload qualification and
default selection. No release image is selected or published by P3.
